Authentication, SSO & Authorization

Flow — Register → Login → Call protected endpoint

1
Register a new user — returns JWT access token + refresh token immediately
↓
2
Use access token in Authorization: Bearer <token> header on every protected call
↓
3
Token expires (60 min default) → Refresh using the refresh token to get a new pair
↓
4
Revoke (logout) — invalidates the refresh token server-side

Register

POST/api/auth/register
Open — no token required
// Request
{
  "email": "alice@example.com",
  "p_w_d": "P@ssw0rd-Example",
  "displayName": "Alice Smith"
}

// Response 200
{
  "success": true,
  "data": {
    "access_token": "",
    "refresh_token": "",
    "expiresAt": "2024-01-15T11:00:00Z",
    "userId": "a3f2...",
    "displayName": "Alice Smith",
    "email": "alice@example.com",
    "roles": ["User"]
  }
}

Login

POST/api/auth/login
{ "email": "alice@example.com", "p_w_d": "P@ssw0rd-Example" }
// → same AuthResponse shape as register

Refresh Token

POST/api/auth/refresh
{ "refresh_token": "" }
// → new AccessToken + new RefreshToken (old one is revoked)

Revoke (Logout)

POST/api/auth/revoke
Requires Bearer token
Authorization: Bearer <your-access-token>
{ "refresh_token": "" }

Who Am I

GET/api/auth/me
Requires Bearer token — returns user from JWT claims

SSO — Google / Microsoft

1
Get redirect URL: GET /api/auth/external/url?provider=Google&redirectUri=https://yourapp/callback
↓
2
Redirect user's browser to that URL — user signs in on Google/Microsoft
↓
3
Provider redirects back with ?code=... — POST it to callback
↓
4
POST /api/auth/external/callback body: {"provider":"Google","code":"...","redirectUri":"..."} → returns JWT + refresh token
Set Sso:Google:ClientId and Sso:Google:ClientSecret in appsettings (or environment variables) to enable Google SSO.

RBAC — Assign Roles

POST/api/users/{userId}/roles
Requires AdminOnly policy
Authorization: Bearer <admin token>
{ "roleName": "Moderator" }

ABAC — Define Permissions & Assign to Role

// 1. Create a permission
POST /api/permissions
{ "name": "posts:create", "resource": "posts", "action": "create", "description": "Can create posts" }

// 2. Assign permission to role (get roleId from GET /api/roles)
POST /api/roles/{roleId}/permissions/{permissionId}

// JWT will now carry:  "permission": ["posts:create"]
// Protect endpoint with:  [Authorize(Policy = "CanCreatePost")]

Built-in ABAC policies

Policy NameRequired ClaimUse On
CanCreatePostposts:createFeed / content endpoints
CanManageUsersusers:manageUser admin endpoints
CanSendEmailemail:sendEmail send endpoints
CanViewLogslogs:viewLog query endpoints
AdminOnlyRole = AdminUser/role management
ModeratorPlusRole = Admin or ModeratorContent moderation

URL Shortener

How codes are made

SQL Server IDENTITY Id → Base62 encoder → 8-char code. Zero collisions, monotonically increasing.

Cache

SQL Server distributed cache, 24h TTL. Resolve hits cache first — DB never touched on repeated redirects.

Shorten a URL

POST/shorten
// Request
{ "url": "https://example.com/very/long/path?with=lots&of=params" }

// Response 200
{
  "success": true,
  "data": { "shortUrl": "http://localhost:5000/1Z3bKx", "code": "1Z3bKx" },
  "message": "URL shortened successfully."
}

Redirect

GET/{code}
Returns 302 redirect to original URL. Same URL always returns same code (dedup by original URL).
GET /1Z3bKx
→ 302 Location: https://example.com/very/long/path?with=lots&of=params

Encryption (AES-256-GCM)

Algorithm

AES-256-GCM — provides confidentiality, integrity, and tamper detection in one operation.

Output format

Base64(12-byte nonce + ciphertext + 16-byte GCM tag). Random nonce per call.

Encrypt

POST/api/encryption/encrypt
// Request — any UTF-8 string: plain text, JSON, emojis, Unicode
{ "plainText": "Hello 你好 🔐 { \"secret\": 42 }" }

// Response 200
{
  "success": true,
  "data": {
    "cipherPackage": "aB3xY9mNpQ2rK5vT...==",
    "algorithm": "AES-256-GCM"
  }
}

Decrypt

POST/api/encryption/decrypt
{ "cipherPackage": "aB3xY9mNpQ2rK5vT...==" }
// → { "success": true, "data": { "plainText": "Hello 你好 🔐 { \"secret\": 42 }" } }

// If tampered: HTTP 400 — DECRYPTION_FAILED

Email Notifications

Flow — Configure → Create Template → Send

1
Create SMTP config — host, port, TLS mode (SslOnConnect/StartTls), credentials (stored AES-256-GCM encrypted)
↓
2
Activate config — only one config is active at a time
↓
3
Create template — subject and HTML body with {{Token}} placeholders
↓
4
Send — pass template name and token values; server renders and delivers

Create SMTP Config

POST/api/email/config
{
  "name": "Production SMTP",
  "host": "smtp.gmail.com",
  "port": 465,
  "tlsMode": 0,          // 0 = SslOnConnect (port 465), 1 = StartTls (port 587)
  "username": "noreply@example.com",
  "smtp_p_w_d": "your-smtp-app-pw",
  "fromAddress": "noreply@example.com",
  "fromName": "BKM System",
  "timeoutSeconds": 30
}
PUT/api/email/config/{id}/activate
Makes this config the active one used for all sends

Create Template

POST/api/email/templates
{
  "name": "WelcomeUser",
  "subject": "Welcome {{FirstName}} to {{AppName}}!",
  "body": "<h1>Hi {{FirstName}}</h1><p>Your account is ready. Code: <b>{{Code}}</b></p>",
  "isHtml": true,
  "description": "Sent when a new user registers"
}

Send via Template

POST/api/email/send/template
{
  "to": "alice@example.com",
  "templateName": "WelcomeUser",
  "variables": {
    "FirstName": "Alice",
    "AppName": "BKM Portal",
    "Code": "VERIFY-7A3X"
  }
}
// → 200 { "success": true, "data": null, "message": "Email sent to alice@example.com." }

Send Raw (no template)

POST/api/email/send/raw
{ "to": "ops@example.com", "subject": "Alert", "body": "Disk usage > 90%", "isHtml": false }

Test SMTP Connection

POST/api/email/test?to=you@example.com
Sends a live test email and returns timing result

Audit Log

GET/api/email/audit?success=true&page=1&pageSize=20
Security note: SMTP password is stored AES-256-GCM encrypted. It is never returned in any API response. The Veracode-clean pure BCL sender enforces TLS (SslOnConnect or StartTls only — no plain-text port 25).

Social Feed — Push & Pull

PushFeed (fan-out on write)

On post → instantly writes one row per follower. Read is O(1) from pre-computed table. Best for <10k followers.

PullFeed (fan-in on read)

Read request aggregates posts from all followees on demand. Best for celebrity accounts / high-follower scenarios.

Push Feed Flow

1
alice follows bob: POST /api/follow?followerId=alice body {"followeeId":"bob"}
↓
2
bob posts: POST /api/posts?authorId=bob body {"body":"Hello world!"} → server fans out to all bob's followers including alice
↓
3
alice reads push feed: GET /api/feed/push?userId=alice → instant O(1) read from pre-computed table

Create a Post

POST/api/posts?authorId=bob
{ "body": "Hello world! 🌍", "mediaUrl": "https://cdn.example.com/img.jpg" }
// → 201 { "success": true, "data": { "id": 42, "code": "bob", "body": "Hello world! 🌍", ... } }

Follow

POST/api/follow?followerId=alice
{ "followeeId": "bob" }

Read Push Feed (pre-computed)

GET/api/feed/push?userId=alice&page=1&pageSize=20
Cache: 60 s TTL. Response includes meta: source="push"
{
  "success": true,
  "data": [
    { "postId": 42, "authorId": "bob", "body": "Hello world! 🌍", "postedAt": "2024-01-15T09:32:00Z" }
  ],
  "meta": { "totalCount": 1, "page": 1, "pageSize": 20, "source": "push" }
}

Read Pull Feed (on-demand)

GET/api/feed/pull?userId=alice&page=1&pageSize=20
Cache: 30 s TTL. Aggregates followees' posts at query time. Response includes meta: source="pull"

Unfollow & List Followees

DELETE /api/follow/bob?followerId=alice     // unfollow
GET    /api/follow/followees?userId=alice    // list who alice follows

Application Logging & Retention

DB sink

Non-blocking Channel<LogEvent> (100k capacity). Never slows request threads. Batched writes of 100 rows.

File sink

Rolling text files via Serilog. Max 10 MB per file, 30 files retained.

Query Logs

GET/api/logs?level=Error&feature=UrlShortener&from=2024-01-01&page=1&pageSize=50
{
  "success": true,
  "data": [
    {
      "id": 1001,
      "level": "Error",
      "message": "Failed to resolve code 'XXXXXX'",
      "feature": "UrlShortener",
      "traceId": "a3f2b1...",
      "timestamp": "2024-01-15T09:00:00Z"
    }
  ],
  "meta": { "totalCount": 3, "page": 1, "pageSize": 50 }
}

Filter params: level (Verbose/Debug/Information/Warning/Error/Fatal), feature, from, to, page, pageSize

Log Retention Policies

GET/api/logs/retention
List all retention policies (null feature = default)
PUT/api/logs/retention
// Set UrlShortener logs to 30-day DB retention, 14-day file retention
{
  "feature": "UrlShortener",
  "dbRetentionDays": 30,
  "fileRetentionDays": 14,
  "description": "Short-lived URL logs"
}

// Set global default (feature = null)
{ "feature": null, "dbRetentionDays": 90, "fileRetentionDays": 30 }

// Set 0 to keep forever
{ "feature": "Encryption", "dbRetentionDays": 0, "fileRetentionDays": 0 }

File Ingestion

One master table dbo.IngestedRecords handles all file types. Every row's data is stored as a JSON object in the Payload column — the schema never changes regardless of how many columns the source file has.

Supported formats

CSV · TSV · Pipe · Fixed-width · JSON Array · JSON Lines · XML · Excel (.xlsx / .xls)

Memory model

Pure streaming — reads one row at a time. A 10M-row file uses <50 MB RAM. Writes in configurable batches (default 500 rows).

Upload Flow

1
POST multipart form to /api/ingest/upload with the file + options
↓
2
Server creates IngestionBatch (status=Processing), detects file type from extension
↓
3
Correct parser streams rows → each row serialised to JSON → SHA-256 hash computed
↓
4
Every 500 rows: duplicate check (hash lookup) → bulk insert non-duplicates → release memory
↓
5
Batch marked Completed with counters: TotalRows / SuccessRows / DuplicateRows / ErrorRows

Upload: CSV with comma delimiter

POST /api/ingest/upload
Content-Type: multipart/form-data

file=customers.csv
recordType=Customer
delimiter=,
hasHeader=true
skipDuplicates=true
batchSize=500

Upload: Pipe-delimited file

file=orders.txt
recordType=Order
delimiter=|
hasHeader=true

Upload: Fixed-width file

file=ledger.dat
recordType=Ledger
fixedWidthJson=[{"name":"AccountId","startIndex":0,"length":10},{"name":"Name","startIndex":10,"length":30},{"name":"Balance","startIndex":40,"length":12}]
hasHeader=false

Upload: Excel

file=report.xlsx
recordType=SalesData
hasHeader=true
// All sheets processed in order. _Sheet column added automatically.

Upload: JSON Lines (NDJSON)

file=events.jsonl
recordType=Event
isJsonLines=true

Upload: XML

file=products.xml
recordType=Product
xmlRecordXPath=/*/*    // depth 2 = children of root element
// <root><product><Id>1</Id><Name>Widget</Name></product>...</root>

Response

{
  "success": true,
  "data": {
    "id": "a4c2e1f3-...",
    "fileName": "customers.csv",
    "fileType": "delimited",
    "recordType": "Customer",
    "totalRows": 50000,
    "successRows": 49987,
    "duplicateRows": 13,
    "errorRows": 0,
    "status": "Completed",
    "startedAt": "2024-01-15T09:00:00Z",
    "completedAt": "2024-01-15T09:00:08Z"
  }
}

Query Ingested Records

GET/api/ingest/records
// Filter by batch
GET /api/ingest/records?batchId=a4c2e1f3-...&page=1&pageSize=50

// Filter by payload field value (searches inside JSON column)
GET /api/ingest/records?recordType=Customer&payloadKey=Email&payloadValue=alice@example.com

// Response row shape
{
  "id": 1,
  "batchId": "a4c2e1f3-...",
  "fileName": "customers.csv",
  "fileType": "delimited",
  "recordType": "Customer",
  "rowNumber": 1,
  "payload": "{\"Id\":\"1001\",\"Name\":\"Alice\",\"Email\":\"alice@example.com\",\"Phone\":\"+1-555-1234\"}",
  "ingestedAt": "2024-01-15T09:00:01Z"
}

List Batches

GET/api/ingest/batches?page=1&pageSize=20
GET/api/ingest/batches/{guid}

Universal API Response Envelope

Every endpoint returns the same envelope shape — success or failure.

{
  "success": true | false,
  "message": "Human-readable summary",
  "data": { ... } | [ ... ] | null,
  "meta": { "totalCount": 100, "page": 1, "pageSize": 20, "source": "push" },
  "warnings": [ "Field X is deprecated" ],
  "errors": [ { "code": "BAD_REQUEST", "message": "..." } ],
  "debug": { "traceId": "...", "timestamp": "...", "stackTrace": "..." }  // dev only
}

HTTP status → error code mapping

HTTPError CodeTriggered by
400BAD_REQUESTArgumentException, validation failure
400DECRYPTION_FAILEDTampered cipherPackage
401UNAUTHORIZEDUnauthorizedAccessException
404NOT_FOUNDKeyNotFoundException, FileNotFoundException
409CONFLICTInvalidOperationException
499TIMEOUTOperationCanceledException
500INTERNAL_ERRORUnhandled exception
The debug block (stackTrace, exceptionType) is only populated when ASPNETCORE_ENVIRONMENT ≠ Production. It is never exposed in production.
